## 1. 多图横排（L3）

**PRD 要求**：Markdown 图片紧挨着不换行 / 多个图片可以放在一行显示。

### 1.1 预览区多图同行

- **操作**：新建文档，源码模式输入（注意两个图片之间没有空格和换行）：

  ```markdown
  ![图1](https://picsum.photos/300/200)![图2](https://picsum.photos/300/200)
  ```

- **预期**：右侧预览两张图并排显示在同一行，各占约 46% 宽度，不换行。
- [ ] 通过

### 1.2 单图仍独占一行

- **操作**：另起一段只放一张图 `![单图](https://picsum.photos/600/300)`。
- **预期**：单图按块级显示，独占一行，宽度撑满正文区（`p img:only-child` 规则）。
- [ ] 通过
- **注意**：这是刻意区分——只有「同段落多图」才横排，避免所有图片都被缩小。

### 1.3 富文本编辑区同样横排

- **操作**：切到「富文本」模式看同一段内容。
- **预期**：编辑区里两张图也并排，与预览一致（本轮新增 `.rich-input p img:not(:only-child)` 规则）。
- [ ] 通过

### 1.4 三张及以上

- **操作**：一行放 3~4 张图。
- **预期**：按 46% 宽度自动折行成两排，不溢出、不撑破容器。
- [ ] 通过

## 2. 进阶导出（L3）

**PRD 要求**：支持 PNG、DOCX、EPUB，自定义导出模板。

准备一篇「综合测试文档」，建议内容覆盖：一级/二级标题各 2 个、加粗/斜体/删除线/行内代码、有序列表、无序列表（含嵌套）、任务列表、引用、代码块、表格、分割线、图片（本地粘贴的 base64 图）、链接、公式、Mermaid 图。

### 2.1 PNG 长图导出

- **操作**：导出 ▾ → 「图片长图 (.png)」，选择保存路径。
- **预期**：
  - 状态栏依次显示「正在生成长图…」→「已导出 <路径>」；
  - 生成的 PNG 是**整篇不滚动的长图**，不是只截了一屏；
  - 图片清晰（2 倍像素密度），中文不糊；
  - 宽度与当前预览区宽度一致，排版和屏幕上看到的相同。
- [ ] 通过
- **边界**：超长文档（逻辑高度 > 16000px）会被裁断，这是 Chromium 窗口高度限制下的有意取舍，需确认裁断处不报错。
- [ ] 超长文档不崩溃

### 2.2 PNG 含 Mermaid / 公式

- **操作**：文档里放一个 Mermaid 流程图和一个 `$$` 块级公式，再导出 PNG。
- **预期**：Mermaid 图已渲染成图形（不是源码文本），公式为 KaTeX 排版结果。
- [ ] 通过

### 2.3 DOCX 导出 —— 能被 Word 打开

- **操作**：导出 ▾ → 「Word (.docx)」，用 Microsoft Word / WPS / LibreOffice 打开。
- **预期**：**不弹「文件已损坏」提示**，正常打开。
- [ ] 通过（这是最关键的一条，失败则下面都不用测）

### 2.4 DOCX 内容还原度

| 元素 | 预期效果 | 通过 |
| --- | --- | --- |
| 标题 H1~H6 | 应用 Word 内置 Heading 样式，可在导航窗格里看到大纲 | [ ] |
| 加粗/斜体/删除线 | 对应 Word 的粗体/斜体/删除线 | [ ] |
| 行内代码 | Consolas 等宽字体、字号略小 | [ ] |
| 无序列表 | 项目符号 •，嵌套层级用 ◦ ▪ 区分并缩进 | [ ] |
| 有序列表 | 自动编号 1. 2. 3.，嵌套用 a. / i. | [ ] |
| 任务列表 | 显示为 `☑ 已完成` / `☐ 未完成` 字符 | [ ] |
| 引用 | 左侧灰色竖线 + 整体缩进 | [ ] |
| 代码块 | 浅灰底、等宽字体、逐行不丢缩进 | [ ] |

| 分割线 | 一条水平细线 | [ ] |
| 图片 | 正常显示（不是红叉），宽度不超出页面 | [ ] |

- **已知取舍**：
  - Mermaid 图在 Word 里降级为**代码块**（Word 无法执行 JS 渲染），源码不丢；
  - 网络外链图片会被**移除**（Word 打开时无法加载，留着只会显示红叉）；
  - 数学公式目前按 KaTeX 生成的 HTML 结构走文本降级，不是 Word 原生 OMML 公式。
- [ ] 上述取舍符合预期，未造成内容丢失

### 2.5 DOCX 图片去重

- **操作**：同一张图在文档里插入 3 次，导出 DOCX 后把 `.docx` 改名 `.zip` 解压。
- **预期**：`word/media/` 下只有 **1 个**图片文件，三处引用同一个（自动去重，体积不翻倍）。
- [ ] 通过

### 2.6 EPUB 导出 —— 能被阅读器打开

- **操作**：导出 ▾ → 「电子书 (.epub)」，用 Calibre / Apple Books / 微信读书导入。
- **预期**：正常打开，不报格式错误。
- [ ] 通过

### 2.7 EPUB 自动分章与目录

- **操作**：文档里写 3 个一级标题（`#`），导出 EPUB。
- **预期**：
  - 阅读器目录里有 3 个章节，章节名 = 各个 `#` 标题文字；
  - 点目录能跳到对应章节；
  - 正文样式（标题层级、代码块、表格）保留。
- [ ] 通过
- **规则说明**：按 `#`（h1）切章；文档没有 h1 时整篇作为一章，章名取文件名。

### 2.8 EPUB 规范合规性

- **操作**：把 `.epub` 改名 `.zip` 解压检查，或用 EPUBCheck 校验。
- **预期**：
  - 第一个条目是 `mimetype`，内容为 `application/epub+zip`，且**未压缩**（STORED）；
  - 存在 `META-INF/container.xml`、`OEBPS/content.opf`、`OEBPS/nav.xhtml`；
  - 所有 `.xhtml` 是合法 XML（自闭合标签规范）。
- [ ] 通过
- **已自动验证**：`npm run test:l3` 生成的样本已通过 Python `zipfile.testzip()`（CRC 校验）与 XML 解析。

### 2.9 自定义导出模板

- **操作 1**：设置面板 → 「自定义导出模板」→ 点「载入默认模板做修改」。
- **预期**：文本框出现内置模板，含 `{{title}} {{style}} {{script}} {{content}}` 占位符。
- [ ] 通过

- **操作 2**：把模板改成带页眉页脚的版本，例如：

  ```html
  <!DOCTYPE html>
  <html lang="zh-CN"><head><meta charset="utf-8"/>
  <title>{{title}}</title><style>{{style}}
  .hdr{border-bottom:2px solid #333;padding:8px 0;margin-bottom:20px;font-weight:700}
  .ftr{border-top:1px solid #ccc;margin-top:30px;padding-top:8px;color:#888;font-size:12px}
  </style>{{script}}</head>
  <body class="markdown-body">
  <div class="hdr">内部资料 · {{title}}</div>
  {{content}}
  <div class="ftr">导出于 {{date}}</div>
  </body></html>
  ```

- **预期**：导出 HTML / PDF / PNG 都带上了页眉「内部资料 · 文件名」和页脚日期。
- [ ] HTML 生效
- [ ] PDF 生效
- [ ] PNG 生效

- **操作 3**：故意填一个不含 `{{content}}` 的模板再导出。
- **预期**：自动回落到内置默认模板，**不会导出空白文件**（防呆保护）。
- [ ] 通过

- **操作 4**：点「清空（用内置）」，重启应用后再看设置面板。
- **预期**：模板框为空，导出结果与改模板之前一致；配置持久化正确。
- [ ] 通过

### 2.10 导出失败不静默

- **操作**：任意导出过程中点「取消」保存对话框。
- **预期**：状态栏提示「已取消 xx 导出」，不残留「正在生成…」，不报未捕获异常。

## 4. 附带完成：左侧编辑区图片点击展开

这一项不在 PRD 的 L3 里，是本轮一并实现的体验优化：把右侧预览「图片点击才显示」的策略同步到左侧富文本编辑区。

### 4.1 折叠展示

- **操作**：导入一个含多张图片的 Word / PDF（转出来是 base64 内嵌图），切到「富文本」模式。
- **预期**：图片位置显示为虚线框占位块「🖼️ 图片：文件名」，不直接渲染大图。
- [ ] 通过

### 4.2 点击展开 / 再点收起

- **操作**：点一下占位块；再点一下展开后的图片。
- **预期**：第一次点击 → 显示真实图片（悬停有蓝色描边、鼠标为 zoom-out）；第二次点击 → 收回成占位块。
- [ ] 通过

### 4.3 大文档不卡顿（核心验收点）

- **操作**：导入一个含 20 张以上高清图、总字数 5 万+ 的文档，在富文本模式下**连续快速打字**。
- **预期**：
  - 打字无明显掉帧、无卡顿；
  - 输入法候选框跟手；
  - 状态栏字数正常刷新。
- [ ] 通过
- **原理**：`getValue()` 每次按键都会跑，序列化时占位块与展开图都只吐 `![alt](@img:3:a.png)` 这样的短占位符，**绝不拼接 base64**。已由 `npm run test:img` 自动验证（展开态输出中不含 `base64,`）。

### 4.4 内容不丢失

- **操作**：在有图文档里编辑文字 → Ctrl+S 保存 → 关闭重开。
- **预期**：图片一张不少，位置正确，能正常展开。
- [ ] 通过

### 4.5 新插入图片

- **操作**：
  1. 截图后直接 Ctrl+V 粘贴到富文本区；
  2. 工具栏「插入图片」→ 本地图片；
  3. 工具栏「插入图片」→ 图片链接（http 地址）。
- **预期**：
  - 1、2 插入后**立刻可见**（刚插入的图默认展开态，不用再点一次），且已登记进 imageStore；
  - 3 网络图片按原样插入，不走占位符（体积小无需折叠）；
  - 三种情况导出 Markdown 时都能拿到完整图片数据。
- [ ] 通过

### 4.6 模式切换一致性

- **操作**：富文本 ↔ 源码 来回切换。
- **预期**：
  - 源码模式看到的是 `![alt](@img:0:xxx.png)` 短占位符（原有行为）；
  - 切回富文本仍是占位块，图片不丢、不重复登记。
- [ ] 通过

### 4.7 图片丢失兜底

- **操作**：（构造场景）占位符 id 在 imageStore 中不存在时点击。
- **预期**：占位块文字变为「🖼️ 图片（已丢失，无法展开）」，不报错、不崩溃。
- [ ] 通过
